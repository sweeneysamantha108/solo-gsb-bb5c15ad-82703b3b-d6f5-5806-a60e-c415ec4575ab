# 字幕核校工具（Python + React）

上传 SRT 字幕与校对稿，服务端归一化标点与空白后，以**词序动态规划**跨字幕块对齐，
识别**缺词、多词、错序、错词**四类文字问题；同时按字幕块执行**时间轴质量审计**，
检查**起止重叠、异常空隙、阅读速度（CPS）**三类时间轴问题。
前端联动展示字幕时间轴与校对稿上下文，可按类型筛选问题，并导出带时间码的核校清单
（CSV / Markdown，含时间轴审计问题与修改建议）。

## 启动（一条命令）

```bash
docker compose up --build
```

启动后访问：**http://localhost:8000**

> 前端在镜像构建阶段编译为静态文件；Python 依赖随容器启动自动安装
> （Compose 已挂载 pip 缓存卷，重复启动很快）。无需任何本地环境。

## 使用

1. 打开页面，选择 SRT 字幕文件与校对稿（纯文本），点击「开始比对」；
   也可点击「使用内置示例」快速体验（示例内置重叠 / 空隙 / CPS 三类时间轴问题）。
2. 结果页三栏联动：**问题清单 | 字幕时间轴 | 校对稿上下文**——
   点击任意问题，三栏自动滚动定位并高亮；点击时间轴审计条目会定位到对应字幕块
   （重叠 / 空隙问题同时标出相邻两块）。
3. 顶部按 缺词 / 多词 / 错序 / 错词 / **时间轴审计** 筛选；
   「全部」视图下文字与时间轴问题按时间码统一排序。
4. 「导出 CSV 清单」「导出 Markdown」导出当前筛选结果；时间轴问题带实测数值与修改建议。

## 时间轴审计阈值

在上传页展开「时间轴审计阈值」即可配置，三个阈值均作用于下一次比对：

| 阈值 | 缺省值 | 含义 |
| --- | --- | --- |
| 重叠容忍 (ms) | `1` | 前一块结束晚于后一块开始达该毫秒数即报「起止重叠」；设为 `0` 则首尾相接不报、任何重叠都报 |
| 最大空隙 (ms) | `3000` | 相邻字幕块之间超过该时长没有字幕即报「异常空隙」 |
| CPS 上限 (字/秒) | `15` | 单块字符数 ÷ 显示秒数超过该值即报「阅读过快」，并给出建议显示时长 |

- 阈值会保存在浏览器本地，**重新比对、重新上传后自动保留**；
- 点击「恢复缺省值」即可回到上表缺省配置（也可通过 `GET /api/thresholds` 查询服务端缺省值）。
- 阈值同样作用于内置示例接口，便于用固定样例调整阈值。

## 核校原理

1. **归一化**：全角转半角、忽略大小写、剔除全部标点与空白（含换行）。
   字幕换行、分块方式与校对稿的差异不会进入比对，从源头避免级联误报。
2. **切词**：CJK 逐字成词，拉丁字母/数字按词成词，每个 token 记录原文位置。
3. **对齐**：字幕 token 跨字幕块拉平成一条序列，与校对稿 token 序列做全局对齐——
   先以 difflib 匹配块为锚点，锚点间用 Needleman-Wunsch 动态规划精对齐
   （匹配 +2 / 替换 -1 / 空缺 -2）。
4. **归并分类**：相邻差异间只隔着 ≤3 个相同 token 时归并为一处问题：
   - 仅校对稿有 → **缺词**；仅字幕有 → **多词**；
   - 两侧字词多重集基本一致 → **错序**；否则 → **错词**。
5. **时间轴审计**：文字比对之外，按字幕块独立扫描——
   相邻块起止重叠、块间异常空隙、单块 CPS 超限，各生成一条带类型、时间码、
   实测数值与修改建议的问题。
6. 每处问题回溯源字幕块时间码与校对稿上下文，生成清单。

## 本地开发

```bash
# 后端（http://localhost:8000）
cd backend && pip install -r requirements.txt
uvicorn app.main:app --reload

# 前端（http://localhost:5173，已代理 /api 到 8000）
cd frontend && npm install && npm run dev

# 核心逻辑自测（无需第三方依赖）
python3 backend/tests/test_core.py
```

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/compare` | multipart 上传 `srt` 与 `script` 文件，返回核校与时间轴审计结果 JSON |
| GET | `/api/sample` | 返回内置示例的结果；支持 `overlap_ms` / `gap_ms` / `max_cps` 查询参数 |
| GET | `/api/thresholds` | 返回时间轴审计缺省阈值 |
| GET | `/api/health` | 健康检查 |

`/api/compare` 的可选表单字段：`overlap_ms`（int）、`gap_ms`（int）、
`max_cps`（float）；留空或缺省即采用服务端缺省阈值。响应在文字问题之外新增：

```jsonc
{
  "timeline_issues": [
    {
      "id": "t1",
      "type": "overlap | gap | cps",
      "timecode": "00:00:28,500 --> 00:00:29,300",
      "start_ms": 28500, "end_ms": 29300,
      "cue": 8, "cue_end": 9,        // 涉及的字幕块序号（0 基）
      "value": 200,                  // 重叠/空隙毫秒数或 CPS 数值
      "value_text": "重叠 200 ms",
      "suggestion": "……具体修改建议……",
      "subtitle_excerpt": "相邻/当前字幕块文本"
    }
  ],
  "thresholds": { "overlap_ms": 1, "gap_ms": 3000, "max_cps": 15.0 },
  "stats": { "timeline_total": 3, "overlap": 1, "gap": 1, "cps": 1 }
}
```

```
├── Dockerfile              # 多阶段：前端构建 + 后端运行时（依赖随启动安装）
├── docker-compose.yml      # 单服务，映射 8000 端口
├── backend/
│   ├── requirements.txt
│   ├── app/
│   │   ├── main.py         # FastAPI 入口、阈值表单参数与静态托管
│   │   ├── tokenizer.py    # 归一化 + 切词
│   │   ├── srt_parser.py   # SRT 解析 / 编码识别
│   │   ├── aligner.py      # 锚点 + Needleman-Wunsch 词序对齐
│   │   ├── analyzer.py     # 差异归并、四类文字问题与审计结果装配
│   │   └── timeline_audit.py # 重叠 / 空隙 / CPS 审计与阈值
│   └── tests/test_core.py  # 核心逻辑自测（含时间轴审计用例）
├── frontend/               # React + Vite
│   └── src/
│       ├── timeline.js     # 审计类型、阈值表单与本地持久化
│       └── components/
│           ├── ThresholdForm.jsx # 阈值表单（可恢复缺省值）
│           ├── StatsBar.jsx      # 含「时间轴审计」筛选
│           └── …
└── samples/                # 内置示例（含缺词/多词/错序/错词与三类时间轴用例）
```
