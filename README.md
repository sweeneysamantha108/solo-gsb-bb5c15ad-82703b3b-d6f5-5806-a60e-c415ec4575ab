# 字幕核校工具（Python + React）

上传 SRT 字幕与校对稿，服务端归一化标点与空白后，以**词序动态规划**跨字幕块对齐，
识别**缺词、多词、错序、错词**四类问题；同时按字幕块做**时间轴质量审计**
（起止重叠、块间异常空隙、阅读速度 CPS），阈值可配置。
前端联动展示字幕时间轴与校对稿上下文，可按类型筛选问题，
并导出带时间码的核校清单（CSV / Markdown，含时间轴审计问题）。

## 启动（一条命令）

```bash
docker compose up --build
```

启动后访问：**http://localhost:8000**

> 前端在镜像构建阶段编译为静态文件；Python 依赖随容器启动自动安装
> （Compose 已挂载 pip 缓存卷，重复启动很快）。无需任何本地环境。

## 使用

1. 打开页面，选择 SRT 字幕文件与校对稿（纯文本），点击「开始比对」；
   也可点击「使用内置示例」快速体验（示例含缺词/多词/错序/错词及
   起止重叠/异常空隙/阅读过快用例）。
2. 结果页三栏联动：**问题清单 | 字幕时间轴 | 校对稿上下文**——
   点击任意问题，三栏自动滚动定位并高亮。
3. 顶部按 缺词 / 多词 / 错序 / 错词 / **时间轴审计** 筛选；
   「导出 CSV 清单 / 导出 Markdown」按当前筛选生成带时间码的核校清单，
   时间轴问题包含类型、时间码、数值与处理建议。
4. 结果页顶部的**时间轴审计阈值**栏可修改阈值并「重新比对」
   （沿用已上传的文件或示例，无需重新选择）；修改后的阈值在重新比对、
   重新上传后都会保留，「恢复默认」一键回到缺省值。

## 时间轴审计与阈值配置

按字幕块独立检查三类问题，与文本差异核校互不影响：

| 检查 | 类型标识 | 触发条件 | 数值 |
| --- | --- | --- | --- |
| 起止重叠 | `overlap` | 上一块结束时间 − 下一块开始时间 > `max_overlap_ms` | 重叠毫秒数 |
| 块间异常空隙 | `gap` | 下一块开始时间 − 上一块结束时间 > `max_gap_ms` | 空隙毫秒数 |
| 阅读速度 | `cps` | 非空白字符数 ÷ 显示时长 > `max_cps`（时长为零直接报告） | 字/秒 |

阈值（缺省值）：

| 参数 | 缺省 | 含义 | 合法范围 |
| --- | --- | --- | --- |
| `max_cps` | `20` | 阅读速度上限（字/秒） | (0, 100] |
| `max_gap_ms` | `2000` | 相邻块允许的最大空隙（毫秒） | [0, 3600000] |
| `max_overlap_ms` | `0` | 相邻块允许的重叠容限（毫秒） | [0, 60000] |

配置方式：上传页「时间轴审计阈值（可选）」折叠区，或结果页顶部的阈值栏；
也可直接通过 API 参数传入（见下）。非法阈值会返回 400 及中文错误说明。

## 核校原理

1. **归一化**：全角转半角、忽略大小写、剔除全部标点与空白（含换行）。
   字幕换行、分块方式与校对稿的差异不会进入比对，从源头避免级联误报。
2. **切词**：CJK 逐字成词，拉丁字母/数字按词成词，每个 token 记录原文位置。
3. **对齐**：字幕 token 跨字幕块拉平成一条序列，与校对稿 token 序列做全局对齐——
   先以 difflib 匹配块为锚点，锚点间用 Needleman-Wunsch 动态规划精对齐
   （匹配 +2 / 替换 -1 / 空缺 -2）。
4. **归并分类**：相邻差异间只隔着 ≤3 个相同 token 时归并为一处问题：
   - 仅校对稿有 → **缺词**；仅字幕有 → **多词**；
   - 两侧字词多重集基本一致 → **错序**；否则 → **错词**。
5. **时间轴审计**：逐块计算阅读速度（CPS），逐对相邻块计算重叠与空隙，
   超过阈值即生成带数值与建议的问题。
6. 两类问题合并为统一清单，按时间码排序、统一编号，
   每处问题回溯源字幕块时间码与校对稿上下文。

## 本地开发

```bash
# 后端（http://localhost:8000）
cd backend && pip install -r requirements.txt
uvicorn app.main:app --reload

# 前端（http://localhost:5173，已代理 /api 到 8000）
cd frontend && npm install && npm run dev

# 核心逻辑自测（无需第三方依赖）
python3 backend/tests/test_core.py
```

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/compare` | multipart 上传 `srt` 与 `script` 文件，返回核校结果 JSON；可选表单字段 `max_cps`、`max_gap_ms`、`max_overlap_ms` 配置时间轴审计阈值 |
| GET | `/api/sample` | 返回内置示例的核校结果；阈值通过同名查询参数传入 |
| GET | `/api/health` | 健康检查 |

响应 JSON 中：`issues` 为统一问题清单（`category` 为 `diff` 或 `timeline`；
时间轴问题带 `value` / `detail` / `suggestion`），`stats` 含各类型计数
（`timeline` / `overlap` / `gap` / `cps`），`thresholds` 回显实际生效的阈值。

## 目录结构

```
├── Dockerfile              # 多阶段：前端构建 + 后端运行时（依赖随启动安装）
├── docker-compose.yml      # 单服务，映射 8000 端口
├── backend/
│   ├── requirements.txt
│   ├── app/
│   │   ├── main.py           # FastAPI 入口与静态托管（阈值参数校验）
│   │   ├── tokenizer.py      # 归一化 + 切词
│   │   ├── srt_parser.py     # SRT 解析 / 编码识别
│   │   ├── aligner.py        # 锚点 + Needleman-Wunsch 词序对齐
│   │   ├── analyzer.py       # 差异归并分类 + 合并时间轴审计
│   │   └── timeline_audit.py # 起止重叠 / 异常空隙 / CPS 审计与阈值
│   └── tests/test_core.py    # 核心逻辑自测（含时间轴审计用例）
├── frontend/                 # React + Vite（阈值表单、时间轴审计筛选与导出）
└── samples/                  # 内置示例（含四类文本差异与三类时间轴问题用例）
```
